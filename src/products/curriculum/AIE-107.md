# AIE-107 — Architecture and Judgement

**2 credits · 32 hours · 5 modules**

> Every other course in this block teaches you to build one thing well. None of them ever asks whether you should have built it at all. This one does nothing else. A customer says 'can AI do this' and the valuable answer is frequently 'you do not need AI for this, you need a rule and a lookup table' — and being the person who says that, with numbers, is worth more than being the person who can wire up any architecture on request.

Every other Block I course teaches you to build one thing well; none asks whether you should have built it. This one does nothing else — rules versus classical ML versus an LLM, decided with measurements, and the human-in-the-loop routing that follows from it.

**By the end you can**

- Decide between rules, a classical model and an LLM for a stated problem, and defend it with numbers
- Produce and read the classification metrics that decision rests on, including calibration
- Set a confidence threshold for human review from data rather than by feel, and state what it costs
- Build a model selection matrix, and a build-versus-buy case a finance-literate reader would accept

**Sitting rule.** Every item is completable in one sitting. Nothing exceeds 180 minutes, and anything over 90 declares its own checkpoints.

## Modules (25 items)

### M1 — When not to use an LLM

*435 minutes*

- **M1.1 · Framing a problem as machine learning** — reading, 90 min, tier 0  
[Machine Learning Crash Course](https://developers.google.com/machine-learning/crash-course)
  *Where:* The framing and classification units — how a problem becomes a label, and when it cannot.
- **M1.2 · An end-to-end classification project** — reading, 90 min, tier 0  
[Hands-On Machine Learning with Scikit-Learn, Keras, and TensorFlow](https://openlibrary.org/isbn/9781098125974)
  *Where:* The end-to-end project chapter and the classification chapter.
- **M1.3 · Choosing what to build** — reading, 60 min, tier 0  
[Building Machine Learning Powered Applications](https://openlibrary.org/isbn/9781492045113)
  *Where:* The chapters on framing a product problem as an ML problem and on choosing a baseline.
- **M1.4 · Three ways to the same answer** — assignment, 180 min, tier 1
  Take the requirement-versus-boilerplate classification inside Career Side Quests. Label at least 200 lines yourself. Then solve it three ways: a regular expression or keyword rule, a classical classifier over TF-IDF features, and the LLM you currently use. Measure all three on the same held-out split for accuracy, cost per thousand lines, and latency. Report which you would ship and why. The regular expression will do better than you expect, and noticing that is the point of the course.
  *Checkpoints:* 200+ lines labelled with a held-out split → all three implemented → accuracy, cost and latency reported for each
- **M1.5 · Retention: approach selection and baselines** — retention, 15 min, tier 1

### M2 — Metrics that make the decision honest

*390 minutes*

- **M2.1 · Metrics and scoring** — reading, 90 min, tier 0  
[Metrics and scoring: quantifying the quality of predictions](https://scikit-learn.org/stable/modules/model_evaluation.html)
- **M2.2 · Probability calibration** — reading, 60 min, tier 0  
[Probability calibration](https://scikit-learn.org/stable/modules/calibration.html)
- **M2.3 · Selective Classification for Deep Neural Networks** — reading, 45 min, tier 0  
[Selective Classification for Deep Neural Networks](https://arxiv.org/abs/1705.08500)
  Abstention as a first-class option — a model permitted to say it does not know.
- **M2.4 · Precision, recall, and what each error costs** — assignment, 120 min, tier 1
  For your M1.4 classifiers, produce confusion matrices and precision-recall curves. Then do the part everyone skips: assign a cost to a false positive and a false negative in this specific product, in whatever unit is real — user trust, wasted review time, a wrong assessment shown to someone. Pick the operating point from that cost, not from the F1 maximum, and say how the choice changes if the costs are reversed.
  *Checkpoints:* confusion matrices and PR curves produced → error costs assigned with justification → operating point chosen from cost
- **M2.5 · Is your confidence a probability?** — assignment, 60 min, tier 1
  Plot a reliability curve for whichever of your three approaches emits a score. If the LLM's stated confidence is not calibrated — it very likely is not — show that, because the next module routes on exactly that number.
- **M2.6 · Retention: classification metrics and calibration** — retention, 15 min, tier 1

### M3 — Human-in-the-loop

*420 minutes*

- **M3.1 · A Gentle Introduction to Conformal Prediction** — reading, 120 min, tier 0  
[A Gentle Introduction to Conformal Prediction and Distribution-Free Uncertainty Quantification](https://arxiv.org/abs/2107.07511)
  The principled way to attach a guarantee to a threshold. Read at least through the classification section; the whole paper is worth it if the maths lands.
- **M3.2 · Human-in-the-loop and continual learning** — reading, 60 min, tier 0  
[Designing Machine Learning Systems](https://openlibrary.org/isbn/9781098107963)
  *Where:* The sections on human-in-the-loop review and on feedback loops from production.
- **M3.3 · Set the threshold from data** — assignment, 150 min, tier 1
  Design a routing policy for your classifier: above a confidence threshold it acts automatically, below it a human reviews. Set the threshold from your calibration work and the error costs from M2.4, not by feel. Report the resulting automation rate, the expected error rate among auto-actioned cases, and the human review load per thousand items. Then state the threshold at which the human becomes the bottleneck.
  *Checkpoints:* policy defined with a derived threshold → automation rate and residual error reported → review load quantified
- **M3.4 · The escalation policy** — assignment, 75 min, tier 2
  Write what the reviewing human actually sees, what they are asked to decide, and what happens to their decision afterwards. A review queue that does not feed back into the system is a cost centre, not a loop. Include what happens when the human disagrees with the model repeatedly.
- **M3.5 · Retention: confidence routing and review design** — retention, 15 min, tier 1

### M4 — Selection, build and buy

*330 minutes*

- **M4.1 · Model selection and build-versus-buy** — reading, 60 min, tier 0  
[AI Engineering](https://openlibrary.org/isbn/9781098166304)
  *Where:* The chapters on choosing a model and on the build-versus-buy decision.
- **M4.2 · Models overview** — reading, 45 min, tier 0 · **optional**  
[Models overview](https://docs.claude.com/en/docs/about-claude/models/overview)
  *Optional because:* The same page is required reading in AIE-101 M1.3, two courses earlier. Re-read only if the capability columns of your matrix feel guessed.
- **M4.3 · A model selection matrix** — assignment, 120 min, tier 2
  Build the matrix you would actually hand a customer: candidate models down one axis, and intelligence, latency, cost, context length, structured output, tool calling, multimodal support and reliability across the other. Populate the cells from your own measurements where you have them and cite the source where you do not. Then apply it to two of your own features and show it producing different answers for each.
  *Checkpoints:* matrix built with sourced cells → applied to two features → different answers explained
- **M4.4 · Build, buy, or call an API** — assignment, 90 min, tier 2
  For one capability in your products, cost four routes over three years: call a frontier API, self-host an open model, fine-tune a small model, or build conventional software with no model at all. Include the costs people leave out — engineering time, on-call, model deprecation, migration when a provider changes terms. State the volume at which the answer changes.
- **M4.5 · Retention: model selection and total cost** — retention, 15 min, tier 1

### M5 — Course project

*390 minutes*

- **M5.1 · Route it** — project, 165 min, tier 3
  Ship a hybrid path in one of your live products: a cheap deterministic or classical component handling the cases it handles well, an LLM handling the rest, and a confidence-based route to human review where neither is trusted. The measurement from M1.4 must be visible in the design — if the LLM handles everything, the report has to show why the cheaper components lost.
  *Checkpoints:* router implemented → each branch justified by a measurement → deployed and reachable
- **M5.2 · The architecture decision record** — project, 90 min, tier 2
  Write the decision record: the problem, the options considered, what each measured, the choice, the cost, and the conditions under which you would revisit it. One page. This is the document that gets you taken seriously in a technical review, and almost nobody writes it.
- **M5.3 · Publish** — project, 75 min, tier 3
  Publish as the next chapter of your public engineering log. This chapter is the one most likely to be read by a hiring manager, because it is the only one that argues against using the technology they are hiring for.
- **M5.4 · Oral defense** — defense, 60 min, tier 4
  Three unscripted questions generated from your report at defense time, answered aloud without notes.
  *Question shapes:*
    - A customer wants an LLM for something a rule would solve. Talk me out of your own product.
    - Your threshold auto-actions 80% of cases. Describe the user harmed by the 20% that slips through.
    - Which cell in your selection matrix are you least confident about, and what would you measure to fix it?
