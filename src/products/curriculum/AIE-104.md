# AIE-104 — Agents and Tool-Use Systems

**4 credits · 59 hours · 9 modules**

> Multi-step reliability is where demos die, and it is an arithmetic problem before it is a prompting problem. A step that succeeds 95% of the time succeeds 60% of the time across ten steps, and no amount of prompt tuning repeals that. This course starts from the arithmetic, spends most of its time on the two things that actually move it — narrower scope and better tool interfaces — and ends by attacking what you built.

Multi-step reliability is where demos die. Compounding per-step error is an arithmetic problem before it is a prompting one.

**By the end you can**

- Derive the reliability of an n-step agent from its per-step success rate, and design against it
- Choose between workflow and agent for a given task and defend the choice
- Sandbox tool access to least privilege
- Evaluate an agent on task completion rather than on transcript plausibility
- Red-team your own agent and report what you got it to do that it should not
- Justify a multi-agent design against a single-agent baseline, or decline to build one
- State what personal data enters a model, where it goes, and what the local regulator expects

**Sitting rule.** Every item is completable in one sitting. Nothing exceeds 180 minutes, and anything over 90 declares its own checkpoints.

## The panel

- **Judges** `claude-opus-5`, `gpt-5`, `gemini-flash-latest`
- **Blind** Judges see the submission and the rubric, never each other's scores, and never the learner's self-assessment.
- **Disagreement** Scores are reported per judge and never averaged into a single number when the spread is 2 or more on any criterion.

### M4 — Reliability under repetition

*375 minutes*

- **M4.1 · tau-bench: tool-agent-user interaction** — reading, 60 min, tier 0  
[tau-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains](https://arxiv.org/abs/2406.12045)
  The pass^k metric is the one to take away: run the same task k times and require every run to succeed. It is the metric a customer actually cares about, and it collapses far faster than pass@1 suggests.
- **M4.2 · LLM Reasoning** — lecture, 60 min, tier 0  
[LLM Agents MOOC \| UC Berkeley CS294-196 Fall 2024 \| LLM Reasoning](https://www.youtube.com/watch?v=QL-FS_Zcmyo) — *Berkeley RDI*
- **M4.3 · pass^k on your own agent** — assignment, 135 min, tier 1
  Run every task from M3.4 eight times. Report pass@1 and pass^8 — the fraction of tasks where all eight runs succeeded. Then answer the question a customer will ask: would you put this in front of their users, and at what pass^k would you change your answer?
  *Checkpoints:* 8 runs per task completed → pass@1 and pass^8 reported → ship-or-not answer with a threshold
- **M4.4 · Design against the decay** — assignment, 105 min, tier 1
  Pick the single intervention you expect to most improve pass^8 — fewer steps, a narrower tool, a verification step, a deterministic fallback — and predict the improvement before implementing it. Then implement and measure. Report the prediction alongside the result whether or not you were right.
  *Checkpoints:* intervention chosen and improvement predicted in writing → implemented → measured against the prediction
- **M4.5 · Retention: reliability metrics and interventions** — retention, 15 min, tier 1

- **M5.4 · Least privilege, enforced rather than requested** — assignment, 165 min, tier 1
  Your M3.4 agent has tool access. Constrain it so the limits hold even when the model tries to exceed them: scoped credentials, an allowlist enforced outside the model, rate and spend caps, and no destructive capability it does not need. Then demonstrate enforcement by instructing the agent directly to exceed each limit and showing that it cannot.
  *Checkpoints:* limits defined per tool → enforcement outside the model → each limit demonstrated to hold under direct instruction

- **M5.6 · What leaks** — assignment, 105 min, tier 1

Then find the leak you did not intend - a system prompt echoed back, another user's data surviving in a shared cache, an error message carrying a payload. Report what you found and what you changed.
  *Checkpoints:* data flow traced per provider → retention and residency stated → one unintended exposure found and fixed
- **M5.7 · Retention: privilege boundaries for tool-using models** — retention, 15 min, tier 1
