**By the end you can**

- Implement linear and logistic regression, and a tree ensemble, from scratch
- Diagnose bias and variance from learning curves
- Choose and justify a metric for an imbalanced problem

## Modules (28 items)

### M1 — Supervised learning, from the update rule

*840 minutes*

- **M1.1 · Regression and classification, derived** — lecture, 150 min, tier 0  
[Stanford CS229: Machine Learning Course \| Summer 2019 (Anand Avati)](https://www.youtube.com/playlist?list=PLoROMvodv4rNH7qL6-efu_q2_bPuy0adh)
  *Where:* The linear regression, normal equations and logistic regression lectures — through the derivation of the logistic update, not just its statement.
- **M1.2 · Training models** — reading, 150 min, tier 0  
[Hands-On Machine Learning with Scikit-Learn, Keras, and TensorFlow](https://openlibrary.org/isbn/9781098125974)
  *Where:* Chapter 4, Training Models — linear regression by normal equation and by gradient descent, then logistic and softmax regression.
- **M1.3 · Linear and logistic regression from scratch** — assignment, 180 min, tier 1
  Implement linear regression twice — once by the normal equation, once by gradient descent — and confirm they agree. Then implement logistic regression, deriving and coding its gradient rather than importing one. Fit all three against scikit-learn on the same data and compare coefficients, not just predictions. Where the coefficients differ, find out whether it is regularisation, the intercept handling, or convergence, and say which.
  *Checkpoints:* Linear regression by normal equation and by gradient descent, agreeing → Logistic regression implemented with its own gradient → sklearn comparison run on identical data → Divergences investigated rather than tolerated
- **M1.4 · Trees and ensembles** — reading, 165 min, tier 0  
[Hands-On Machine Learning with Scikit-Learn, Keras, and TensorFlow](https://openlibrary.org/isbn/9781098125974)
  *Where:* Chapters 6 and 7 — decision trees, then bagging, random forests, and gradient boosting.
- **M1.5 · A decision tree, then a forest** — assignment, 180 min, tier 1
  Implement a decision tree: the split criterion, the greedy search, and a stopping rule you choose deliberately. Verify the impurity calculation by hand at one node. Then wrap it in bagging and measure what averaging over bootstrap samples does to variance across random seeds. Report the variance before and after, because 'ensembles reduce variance' is a sentence everyone repeats and few have measured.
  *Checkpoints:* Split criterion implemented and its value verified by hand on one node → Tree grown with a stated stopping rule → Bagging added over the tree → Variance reduction measured across seeds
- **M1.6 · Retention: model families and what each assumes** — retention, 15 min, tier 1

### M2 — Bias, variance, and what the curves say

*720 minutes*

- **M2.1 · Learning theory and the bias-variance decomposition** — lecture, 180 min, tier 0  
[Stanford CS229: Machine Learning Course \| Summer 2019 (Anand Avati)](https://www.youtube.com/playlist?list=PLoROMvodv4rNH7qL6-efu_q2_bPuy0adh)
  *Where:* The bias-variance and learning theory lectures, including the discussion of where the decomposition stops being a useful picture.
- **M2.2 · Generalisation, and splitting data honestly** — reading, 165 min, tier 0  
[Machine Learning Crash Course](https://developers.google.com/machine-learning/crash-course)
  *Where:* The generalisation, training-and-test-sets, and validation units — particularly why a test set consulted repeatedly stops being one.
- **M2.3 · Learning curves that actually diagnose** — assignment, 180 min, tier 1
  Deliberately produce one model that underfits and one that overfits the same dataset. Plot training and validation error against training set size for both. Then write the part that makes this useful later: given only the shapes of these curves, what tells them apart, and what would you do next in each case. A curve you cannot act on is decoration.
  *Checkpoints:* An underfitting model produced and its curve recorded → An overfitting model produced and its curve recorded → Both curves plotted with training and validation on the same axes → The distinguishing feature named
- **M2.4 · Diagnose something you actually run** — assignment, 180 min, tier 2
  Take a model or scoring component from something you have shipped. Produce learning curves from its real data. State a diagnosis — more data, more capacity, better features, or the problem is not learnable as framed — and commit to it in writing before trying anything. Then act on it and measure. Retracting a diagnosis that the measurement refuses to support is a full-marks outcome; quietly changing it is not.
  *Checkpoints:* A real model or pipeline of your own chosen and described → Curves produced from its real data → A diagnosis stated before any fix is attempted → The fix applied and re-measured, or the diagnosis retracted
- **M2.5 · Retention: reading a learning curve** — retention, 15 min, tier 1

### M3 — Features, and the ways they lie

*600 minutes*

- **M3.1 · An end-to-end project, for the pipeline** — reading, 150 min, tier 0  
[Hands-On Machine Learning with Scikit-Learn, Keras, and TensorFlow](https://openlibrary.org/isbn/9781098125974)
  *Where:* Chapter 2, End-to-End Machine Learning Project — the data preparation, transformation pipeline and custom transformer sections.
- **M3.2 · Features that earn their place** — assignment, 180 min, tier 1
  Take one of your own datasets. Measure a baseline on raw features before engineering anything. Then add engineered features one at a time and measure the lift of each. Report the ones that gained nothing and remove them. The deliverable is not a better model; it is a table of which ideas worked and by how much, including the ones that felt obviously right and did nothing.
  *Checkpoints:* A baseline with raw features measured first → Each engineered feature added one at a time → Lift measured per feature against the baseline → Features with no lift removed and reported
- **M3.3 · Find the leak** — assignment, 150 min, tier 2
  Introduce target leakage into a pipeline on purpose — a feature computed after the fact, or a scaler fitted before the split — and measure how good it makes your model look. Then design a procedure that would have caught it without knowing where it was, and run that procedure against a pipeline you actually use. Report what it found, including nothing.
  *Checkpoints:* A leaking feature introduced deliberately and its effect measured → The leak detected by a stated procedure rather than by knowing where it was → The procedure applied to a real pipeline of your own
- **M3.4 · Framing the problem before the features** — reading, 105 min, tier 0  
[Building Machine Learning Powered Applications](https://openlibrary.org/isbn/9781492045113)
  *Where:* The chapters on framing the problem and on building a first end-to-end pipeline — where the choice of label is shown to matter more than the choice of model.
- **M3.5 · Retention: leakage and feature evaluation** — retention, 15 min, tier 1

### M4 — Unsupervised, and its temptations

*600 minutes*

- **M4.1 · Dimensionality reduction and clustering** — reading, 165 min, tier 0  
[Hands-On Machine Learning with Scikit-Learn, Keras, and TensorFlow](https://openlibrary.org/isbn/9781098125974)
  *Where:* Chapters 8 and 9 — PCA and its variants, then k-means, DBSCAN and Gaussian mixtures.
- **M4.2 · Cluster the corpus you already decomposed** — assignment, 180 min, tier 1
  Reuse the term-document matrix you built for AIE-201's decomposition assignment. Cluster it, choosing k by a method you state in advance rather than by looking. Then do the thing that makes this worth doing: compare the clusters against the singular vectors you already interpreted. If they agree, say what that tells you. If they disagree, say which one you believe and why — that is the interesting outcome and it is the one people quietly drop.
  *Checkpoints:* The same corpus and matrix used as in AIE-201 M1.5 → k chosen by a stated method before inspecting the clusters → Clusters compared against the SVD components from the earlier assignment → Agreement or disagreement reported with examples
- **M4.3 · Where clustering told you nothing** — assignment, 150 min, tier 2
  Run k-means on data you know has no cluster structure — uniform noise will do — and show that it returns clusters anyway, with a plausible-looking plot. Apply a validity measure such as silhouette and report what it says. Then write the rule you will actually use: what would have to be true before you present a clustering to anyone as a finding.
  *Checkpoints:* Clustering run on data with no real cluster structure → The algorithm's output shown to be confident anyway → A validity measure applied and reported → A rule written for when not to trust a clustering
- **M4.4 · k-means, EM and PCA, derived** — lecture, 90 min, tier 0  
[Stanford CS229: Machine Learning Course \| Summer 2019 (Anand Avati)](https://www.youtube.com/playlist?list=PLoROMvodv4rNH7qL6-efu_q2_bPuy0adh)
  *Where:* The k-means, mixture-of-Gaussians with EM, and PCA lectures.
- **M4.5 · Retention: unsupervised methods and their failure to abstain** — retention, 15 min, tier 1

### M5 — Metrics, imbalance, and being believed

*840 minutes*

- **M5.1 · Metrics and scoring** — reading, 120 min, tier 0  
[Metrics and scoring: quantifying the quality of predictions](https://scikit-learn.org/stable/modules/model_evaluation.html)
- **M5.2 · Probability calibration** — reading, 120 min, tier 0  
[Probability calibration](https://scikit-learn.org/stable/modules/calibration.html)
- **M5.3 · A metric chosen for a reason** — assignment, 180 min, tier 1
  Take an imbalanced problem and state its base rate. Score a majority-class baseline under accuracy, precision, recall, F1, ROC-AUC and average precision, and show which of those the baseline can win. Then choose the metric you would report, justifying it by what a false positive and a false negative actually cost in that setting — not by which is conventional.
  *Checkpoints:* An imbalanced problem taken or constructed, with the base rate stated → A majority-class baseline scored under every candidate metric → The chosen metric justified against the cost of each error type → The model compared against the baseline under that metric
- **M5.4 · Calibrate, and show the reliability diagram** — assignment, 165 min, tier 2
  Produce a reliability diagram for a classifier of yours and report its calibration error. Apply Platt scaling or isotonic regression on data the model has not seen, and reproduce the diagram. Then check what calibration did to your ranking metric — it is usually close to nothing, and knowing that calibration and discrimination are separate properties is the point of the assignment.
  *Checkpoints:* Reliability diagram produced before calibration → A calibration method applied on held-out data → Diagram reproduced after, with a calibration error reported → The effect on the ranking metric checked
- **M5.5 · The baseline that should have been there** — project, 180 min, tier 3
  Go back to the requirement-versus-boilerplate comparison from AIE-107, where the classical model was whatever scikit-learn offered by default. Rebuild it properly: chosen features, tuned hyperparameters, a metric justified for the imbalance, and calibration if it matters. Publish the result as a chapter of the public log, connected back to the original. State plainly whether the verdict changes. If a well-built classical model now beats the LLM you shipped, that is the most valuable sentence in the programme so far and it must be written down.
  *Checkpoints:* The AIE-107 comparison revisited with a properly built classical model → Tuning, features and metric choice documented → The verdict restated, whether or not it changes → Published and connected backwards to the earlier chapter
- **M5.6 · Oral defense** — defense, 60 min, tier 4
  Three unscripted questions generated from your own submissions at defense time, answered aloud without notes.
  *Question shapes:*
    - Your bagged trees reduced variance. By how much, and how would you know if the reduction were noise?
    - You reported average precision rather than ROC-AUC. Someone senior says AUC is standard. Answer them.
    - Your clusters disagreed with the SVD components. Which did you believe, and what would change your mind?
- **M5.7 · Retention: metric selection and calibration** — retention, 15 min, tier 1

## Completion

- All nine assignments, the project and the defense submitted. Readings and lectures are tier 0 and are tracked but never counted toward mastery.
- Deterministic. Each item's tier sets its weight; panel scores enter as per-criterion values; nothing is rounded up. Computed in TypeScript, never by a model.
- Sets initial mastery on all four machine-learning skills, and is the course that makes AIE-102's evaluation vocabulary mean something mechanical rather than borrowed. FSRS then decays them.
